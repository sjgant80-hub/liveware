How it works

Five moves, one loop. A signed seed grows the system; a door on the raw bytes defends a deliberately naive core; LIGHT keeps everything small and lossless; a mesh lets two copies find each other with no server; and every step writes a receipt anyone can re-run. The organism grows, defends, remembers, improves, and proves — then reproduces a verified copy of itself.

The seed

Magic, length, a LIGHT-encoded genome (every block pinned by SHA-256), a seal, and an Ed25519 signature over everything but itself. It checks magic, length, decode, shape, seal, signature, then each block's hash — only then does a block load.

The door & immune system

A signed-packet door checks size, magic, version, length, dictionary, sender, signature and replay counter on the raw bytes before the body is decoded. Every refusal mints two antibodies: the exact bytes, and their shape.

LIGHT compression

A context-mixing arithmetic coder — seven models blended by weights that learn as they go, integer-only so encoder and decoder agree bit for bit on every engine, and lossless back to the original.

The mesh

Each tab has its own key; they meet over the browser's channel (trust-on-first-use pins the key), then every message is a signed LIGHT packet checked against that key and a replay counter, with one shared document merged by a conflict-free law.

How the proof works

Sealed claims

The pass criteria were written and committed before any code that measures them. The measurement refuses to run if the sealed file changed, and the commit is on this page.

Receipts

Each test writes a record of its inputs, outputs and verdict; its id is the SHA-256 of that record. Your run's id must match the expected id shown beside each test.

CI reproduces it

GitHub Actions runs the same tests headlessly on every change and publishes the receipts. A third party reproduces the result, not just us.

Mutation testing

The witness plants a bug in every kernel and fails the build unless a test catches it — proof the tests are real, not decoration. Failures are kept on the record, never hidden.

FAQ

Is this real or a demo?

Every claim on this page runs live in your browser and gives you a receipt you can check. The same tests run publicly on GitHub and get the same answers.

Does any of my data leave my device?

No. The page works offline once loaded. Files you drop in are processed locally and never uploaded.

Why do you show the tests that fail?

Because a record that includes its losses is one you can believe. The compression rows where LIGHT barely wins stay on the table; any failed claim stays on the page.

Do I need a powerful computer?

Most tests run on any modern browser, on plain CPU. The AI tests (Wave 2) need a browser with WebGPU; if yours doesn't have it, they're skipped and marked.

Can I use this for my company?

Yes. Start with one process and a signed baseline — see “For business” above.

Is it open source?

The core is open; see the repository for licences and credits. Code is MIT.
